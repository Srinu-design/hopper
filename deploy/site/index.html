Hopper · What it does

Everything a production job queue needs, each feature proven by a test.

See the tests

  • One worker per job

    Workers claim rows with SKIP LOCKED, so no two ever get the same job.

  • Crash recovery

    A killed worker's jobs come back when its lease runs out and finish on another.

  • Fencing tokens

    A worker that was paused too long can't overwrite the newer run.

  • Retries with backoff

    Full-jitter exponential backoff, with limits set per task.

  • Dead-letter queue

    Jobs that keep failing are parked with their history, and can be replayed.

  • Idempotency keys

    A retried request returns the same job instead of creating a second one.

  • Delayed and cron jobs

    Run later, at a set time, or on a schedule. Two schedulers, never a double fire.

  • Many tenants

    Each tenant sees only its own jobs and has its own rate limit and queue quota.

  • Backpressure

    Over the limits, the API answers 429 or 503 with Retry-After instead of falling over.

  • Webhook jobs

    The http task calls your URL, signed, with an SSRF guard.

  • Metrics and alerts

    Prometheus metrics from every process, five alerts and a dashboard.

  • Safe deploys

    Every merge deploys itself; a bad release rolls back with no one involved.

Architecture

One image runs every role.

Caddy is the only public entry point. The API, workers and schedulers keep no state of their own: PostgreSQL holds every job, and Redis holds only rate-limit buckets and a cached queue depth, so losing Redis loses no job.

  1. 01 · Entry

    Caddy

    The only public port. Checks both API replicas every 2 s.

  2. 02 · API

    API × 2

    Checks the key, the rate limit and the queue depth, then writes the job row.

  3. 03 · State

    PostgreSQL 16

    Every job. The queue and the source of truth.

    Redis 7

    Rate-limit buckets and a cached queue depth, nothing else.

  4. 04 · Work

    Workers × 3

    Claim with SKIP LOCKED, renew leases, ack or nack.

    Schedulers × 2

    Cron, the lease reaper, queue depth and cleanup.

Reliability

When things break.

Delivery is at least once: if a worker dies at the wrong moment, a job can run twice, but an accepted job is never lost. Exactly-once is impossible when workers can crash, so handlers are written to be safe to repeat.

Sift · What it does

Question answering over your documents that cites the section behind every claim, refuses when the evidence is missing, and proves every retrieval change with a measured eval.

  • Cites every claim

    Every sentence of an answer cites a numbered source with its section or page, and code rejects any citation that does not point to a retrieved chunk.

  • Refuses without evidence

    Two gates: a low rerank score refuses before any model call, and the model itself may refuse. Refusal precision and recall are measured.

  • Measured

    A versioned golden set of 141 questions. CI runs the retrieval eval on every pull request and fails the build on a regression.

  • Multi-tenant

    Each customer sees only its own documents: tenant filters plus row-level security in Postgres, with tests for chunks, answers and cache entries.

  • Ingestion on Hopper

    Parse, embed and activate run as Hopper jobs, with retries, a dead-letter queue and replay.

How it works

The query path.

  1. 01

    Auth and tenancy

    The tenant comes from the API key, never the request; every transaction is scoped to it, and row-level security is the second layer.

  2. 02

    Answer cache

    Keyed by tenant, collection, index version, strategy, filters, prompt version, model and the normalised question.

  3. 03

    Dense and lexical search

    Dense top 50, pgvector HNSW; lexical top 50, Postgres full-text. Both run concurrently, with metadata filters inside both.

  4. 04

    Fusion

    Reciprocal-rank fusion with k = 60 merges the two lists.

  5. 05

    Rerank

    A cross-encoder rescores the fused top 30; the top 8 go to the model.

  6. 06

    Gate 1

    If the best rerank score is below τ = 0.19, Sift refuses without calling the model.

  7. 07

    Answer and check

    The model returns JSON with [S#] markers and short quotes; code checks every id, every quote, and that every sentence cites. One retry, then refusal.

  8. 08

    Gate 2

    The model may refuse itself. The query is logged with timings per stage, tokens, cost and the gate.
